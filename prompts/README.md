# 提示词：让内部 Agent 自己整理盘点表 / 表卡 / 逻辑卡

> 结论：三份都可以让内部 Agent 根据项目实际脚本生成，不用人工从零写。
> 分工原则不变：脚本和提取器能给的事实由 Agent 填；脚本里没有的信息
> （调度频率、是否在跑、负责人、字段业务含义、历史口径变更）
> Agent 一律标「待人工确认」并在最后汇总成人工待办清单，不许猜。
> 人工最后只补这张清单，比从零写省得多。

## 顺序（别乱，逐份依赖前一份）

1. `01-pilot-inventory.md`：先扫描 + 跑提取器，产出盘点表和 `lineage.json`。
2. `02-table-card.md`：基于血缘和脚本/DDL 生成表卡。
3. `03-logic-card.md`：基于血缘（含全局反查下游）生成逻辑卡。

## 用法

- 每份文件里代码块就是完整提示词，整体复制粘贴给内部 CLI 即可，
  只需把其中的 `<尖括号>` 部分换成本地实际路径/范围
  （尖括号是提示词参数，和还原用的 `{{...}}` 占位符不是一回事）。
- 三份提示词的共同纪律已写在各自文本里：只读不改原 `.sql`、
  事实只来自脚本原文/提取器输出/项目内 DDL/UDF 清单、
  推断必须标注「推断」及依据、拿不到的标「待人工确认」。
- 每份跑完先抽查它报告里的抽查项，再让它批量继续；
  模型是 Flash 版，一次让它处理太多文件容易糊弄，
  盘点表可以全量，表卡/逻辑卡建议按目录或链路分批跑。
