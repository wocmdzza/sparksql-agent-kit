# SparkSQL 编写规范（Skill 的格式依据）

> Skill 写 SQL 时按本文件执行。状态标记：
> 使用者 已确认，Agent 必须执行；
> 2026-11-06 使用者 明确先不额外设置、保持现状——
> Agent 不许把此前建议的默认值当规范执行，改老脚本时沿用原脚本
> 现有写法，新脚本遇到这类问题先问或保持朴素写法；
> 仍需 使用者 给事实。

## 1. 分区规则

项目所有脚本的分区只用这三个名称，从未用过 `dt` 等其他命名；
遇到其他分区名视为异常，先问，不许当成同义词自行替换。

| 分区字段 | 取值格式 | 含义 | 规则 |
| -------- | -------- | ---- | ---- |
| `pt_d` | `yyyyMMdd`（如 `20261106`） | 该脚本运行周期对应的日期（天） | 读表必须带 `pt_d` 过滤（全量快照表等例外须在表卡注明并在方案里说明）；写入用 `PARTITION(pt_d=...)` |
| `pt_h` | `HH`，`00`–`23` | 该脚本运行周期对应日期的小时；如 `00` 分区保存 `00:00:00`–`00:59:59` 的数据 | 小时粒度表除 `pt_d` 外还必须带 `pt_h` 过滤/写入 |
| `device_type` | 固定枚举（见下） | 设备类型 | 需求只涉及单设备类型时必须带过滤；涉及全部设备时在方案里明说不加过滤，不要默认全扫 |

- `device_type` 枚举：已知的有 `Phone`、`Tablet`、`Vision` 等，
取值大小写按此写法。完整枚举由 使用者 后续补在本节（占位符
`{{DEVICE_TYPE_ENUM_FULL}}`，还原方式见根目录 `RESTORE.md`），作为全局清单使用；
清单里没有的值不许自创，涉及未列出的设备类型时先问。
- 多级分区排序：`PARTITION(...)` 按 天、小时、设备类型 的顺序，
即 `pt_d, pt_h, device_type`（只写实际用到的层级，保持相对顺序）。

## 2. 排版格式

- 关键字大小写：默认小写；以提出需求时的要求为准，
某次需求里指定了其他大小写就按那次的来。
- 逗号：字段前逗号（行首逗号），如：

```sql
select user_id
,device_type
,count(1) as cnt
```

- 以下暂不设置：缩进空格数、一列一行还是紧凑排列、
分号与多语句的间隔写法。保持现状，不强制。
- 格式化工具注意：sqlglot 的默认 format 输出是关键字大写 +
尾随逗号，与上面两条已定规则冲突，所以 **sqlglot 只用于解析和
血缘/分区校验，不用它的默认 format 结果当最终排版**；
最终排版由 Agent 按小写 + 前逗号手工对齐。

## 3. 命名

表层级前缀、临时表/临时视图命名、CTE 命名、表别名、字段别名
是否必须带 `AS`——暂不额外设置，保持现状：改老脚本沿用原命名风格，
新脚本不许自创层级前缀。

## 4. 写法规矩

字段引用是否必须带别名限定、join 写法细则、去重的选用场景、
日期推算函数的偏好、空值默认值习惯、每脚本默认 `SET`——
暂不额外设置，保持现状。
已定红线不变（在 SKILL.md 里）：禁止 `SELECT *` 落表、
禁止无分区全表扫描、变量只用 `set` + `${...}`。

## 5. 文件与交付

- 正式脚本注释头 + `@Modify`：见 `templates/script-header.md`
- 文件命名、文件存放目录结构、本地 Git 提交信息格式：暂不额外设置，保持现状。
