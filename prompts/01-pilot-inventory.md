# 提示词 1：生成试点盘点表（pilot-inventory）

前置：无。产出：填好的盘点表 + `lineage.json`。把下面整段复制给内部 Agent：

```text
任务：根据项目脚本自动生成试点盘点表，不要让我手工填。

1. 先读模板 templates/pilot-inventory.md，严格按它的列和口径输出。
2. 在 PowerShell 里对 <脚本目录> 跑提取器（只读，不改任何 .sql）：
   uv run --with sqlglot python scripts\extract_lineage.py <脚本目录> > lineage.json
   lineage.json 保存到项目根目录，后续表卡/逻辑卡还要用。
3. 一行 = 一个产出表：一个脚本产多张表拆多行，备注写「同一文件」；
   没有 INSERT/CREATE 产出表的脚本（纯查询/分析）单独列在表后
   「无产出表脚本」一节，不要混进盘点行。
4. 各列怎么填，只许用下列证据，不许猜：
   - 产出表、输入表：以 lineage.json 为准。
   - 脚本文件：相对 <脚本目录> 的路径。
   - 复杂度：按机械规则判定——简单：单表、无 join；
     中等：有 join 或多层 CTE；复杂：有临时表/临时视图、
     窗口函数去重、倾斜处理、或单文件多产出表。备注里写判定依据。
   - 调度频率、是否在跑：脚本里看不出来。注释头/文件内容里有明确
     写明的才填并注明出处，否则一律填「待人工确认」，不许根据
     文件修改时间或命名推测在跑状态。
5. 备注列还要标：解析错误（抄 lineage.json 的 parse_errors）、
   表名嵌 ${...} 需人工复核的、用到自定义 UDF 的（列函数名）。
6. 输出：覆盖写回 templates/pilot-inventory.md 同结构的本地文件
   docs/pilot-inventory-filled.md（不要改模板原文件），行数不限于 30，
   有多少产出表写多少行，按脚本文件路径排序。
7. 最后报告：扫描文件总数、盘点行数、无产出表脚本数、解析失败数，
   并随机抽 3 行把产出表/输入表与 lineage.json 原文对照贴出来自证。
```
