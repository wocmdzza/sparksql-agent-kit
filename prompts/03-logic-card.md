# 提示词 3：生成逻辑卡（logic-card）

前置：先跑完提示词 1（有 `lineage.json` 和盘点表）；UDF 清单
`docs/udf-catalog.md` 已在本地填好。产出：
`docs/logic-cards/<产出表>.md`，一产出表一卡。把下面整段复制给内部 Agent：

```text
任务：为 <目标脚本范围，如：盘点表中的核心脚本> 逐个生成逻辑卡，
不要让我从零写。

1. 先读模板 templates/logic-card.md，严格按模板结构输出；
   再读 docs/udf-catalog.md，卡里涉及的 UDF 含义只能引这份清单，
   清单里没有的函数标「UDF 清单未收录」。
2. 事实来源：该脚本原文 + lineage.json。不许引入脚本外的业务知识。
3. 各节填法：
   - 产出表/粒度：产出表以 lineage.json 为准；粒度按 INSERT 的
     SELECT 的 GROUP BY/去重逻辑推断并标「推断，待人工确认」。
   - 输入表：抄 lineage.json，并逐表补 join 键和分区过滤
     （pt_d/pt_h/device_type 实际写法照抄原文，不要改写成别的格式）。
   - 核心口径：按 CTE/临时视图的先后顺序逐段一句话概括每段在做什么
     （过滤了什么、按什么聚合、用什么键去重）；指标的计算式按代码
     字面写清，如「活跃 = count(distinct user_id)，过滤条件 ...」；
     代码里看不出业务原因的，写「按代码字面：...，业务口径待人工确认」，
     不许替业务编定义。
   - 分区规则：照抄该脚本实际的分区写法（写入 PARTITION 子句、
     读取过滤、pt_d 取值来源是常量/set 变量/上游字段）。
   - 下游影响：用 lineage.json 全局反查——哪些其他脚本的输入表
     包含本产出表，就列哪些；查不到写「血缘范围内无下游」，
     不许漏查后写「无」。
   - 来源脚本：相对路径 + 文件最后修改时间（用文件属性，不要猜）。
   - 坑/历史：脚本注释里写了的才抄并注明出处；没写的标
     「待人工确认」，不许根据代码风格推测历史口径变更。
4. 输出：一产出表一文件 docs/logic-cards/<产出表>.md；
   不要在卡里大段粘贴原 SQL，只引用 CTE 名和行号定位。
5. 分批执行：一批最多 <5> 个脚本，复杂脚本（多产出/多层临时表）单独成批。
6. 每批最后自查并报告：随机抽 1 张卡，把它的 join 键、分区过滤与
   lineage.json 原文对照贴出；再汇总本批所有卡里的
   「待人工确认」成一份清单贴出来，我只补这份清单。
```
